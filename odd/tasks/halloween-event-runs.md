# Halloween event runs

Objective: a Halloween gauntlet event (8 Edison bot waves, cumulative prizes) built on a generic, server-authoritative "reserved duel" capability that also supports duels between two humans.
Repos and branches: EDOpro-server-ts `feat/halloween-bots` → `feat/reserved-duels`; evolution-api `feat/event-runs` (from `main`); evolution-card-game `feat/halloween-event`; windbot `feat/halloween-horde-bots`; evolution-assets `feat/halloween-decks`. Delivery: ask-on-risk (forecast well above 400 lines: chained PRs per repo). Test runners: `bun test` (api), `npm test` / jest (server), vitest touched files + build (client).
Design: `evolution-api/docs/design/halloween-event-runs.md` (Judgment Day APPROVED twice; contract generalized afterwards, re-review on code).

## Specs

- S1 Event loop. User, verbatim: "se le da a un jugador un deck aleatorio tematico de hallowen o tal vez que elija entre 3-5 ... juega con distintos bots hasta que pierda, los bots van subiendo de dificultad conforme vaya avanzando, hasta que logren vencer al jugador, dependiendo de la cantidad de bots (zombies) derrote el jugador se le dara un premio". Decided: pick 1 of 3 fixed decks (Necromancer, Dark World, Cursed Garden); 8 waves in order Haunted, Skeletons, Horde, Archfiends, Vampires, Witches, Lich, Gravekeepers (user: "dejalo asi"); first loss ends the run; disconnect = loss; draw = loss.
- S2 Client flow. User, verbatim: "mi idea es que se vea un banner en evoduel, el cliente de click, salgan algunos mensajes tematicos y empiecen los duelos!" Banner on home, narrator messages, deck choice, wave ladder, interstitial between waves, summary after the loss.
- S3 Server boundary. User, verbatim: "lo que he venido haciendo hasta ahora es evitar que el servidor tenga otra responsabilidad fuera de los duelos me gustaria que permanezca asi". The duel server knows only reserved duels; it never calls the API and never learns events, runs, waves, attempts or prizes.
- S4 Server-authoritative results: the client never reports a result; progress comes only from server-written duel records applied by the API.
- S5 Prizes: cumulative tiers at 3 / 5 / 8 waves cleared, granted when a tier is crossed, once per tier and player (best mark). Contents configurable in the event catalog; the user designs new exclusive cosmetics (user: "yo puedo diseñar nuevos cosmeticos, me parece bien").
- S6 Attempts: limited runs per day per player, configurable in the catalog. Default 3 per day (user, verbatim: "si, 3 por dia").
- S7 Reuse for future events and tournaments. User, verbatim: "dejalo funcionando para dos humanos tmb". The reservation contract supports two human seats, single or best-of-3 mode, spectators, listing, reconnect and exact or registered deck locks, with no server change.
- S8 Quality over deadline. User, verbatim: "no le prestes atencion a la fecha trabaja pensando q tienes todo el tiempo dl mundo".
- S9 Wave pools. User (verbatim): "se me ocurre que podemos aprovechar los mazos que tenemos para los players tmb como bots", "solo en la oleada, no practica", then "si" to: 8 waves, each wave draws its rival from a difficulty pool — waves 1-2 easy {Haunted, Skeletons, Horde}; 3-4 medium {Archfiends, Vampires, Witches}; 5-6 hard {DarkWorld, CursedGarden, Necromancer} (the player decks piloted as bots); 7 Lich; 8 Gravekeepers. The rival is drawn when the wave becomes current, never the player's own deck, never a bot already faced in the run. Prize tiers stay 3/5/8.
